## 一、实验目的

1. 掌握把 `uni.request` 统一封装成**服务层**的方法：集中 `baseURL`、统一超时、统一错误处理，
   让页面代码不再关心 HTTP 细节。
2. 用 Promise / `async-await` 组织异步流程，并能准确区分「请求中、成功、失败」三种运行状态。
3. 实现列表页的**加载中、空数据、网络失败**三态界面，理解状态机比 `if-else` 堆叠更可维护。
4. 用本栈 KV 存储（`uni.setStorageSync`，H5 落 localStorage）做数据持久化，验证**重启应用后仍在**。
5. 建立数据安全意识：本地不明文存储密码等敏感信息，改用脱敏 + 加盐摘要 + 过期控制。

## 三、需求分析

题目 5 条要求，拆成可验证的功能点：

| # | 题目要求 | 可验证的验收点 |
| --- | --- | --- |
| 1 | 请求统一封装 | 域名/超时只出现在一个文件；页面里没有裸 `uni.request`；错误只有一种对象形状 |
| 2 | Promise / async-await + 三态 | 页面能观察到 `loading → success / error` 的切换；失败有可读文案 |
| 3 | 列表中/空/失败三态 | 三种状态各有一个稳定可复现的界面（演示开关可控） |
| 4 | KV 持久化 | 刷新页面 / 重开进程后，上次加载时间、登录态仍在 |
| 5 | 敏感信息不明文存储 | 存储明细里看不到密码原文；只有盐 + 摘要 + 脱敏账号 |

真实网络不可控（且本机 `github.com:443` 不通），因此服务层内置**本地 mock 适配器**：
它返回与 `uni.request` 完全相同的回调结构（`{ statusCode, data }` / `{ errMsg }`），
所以「切到真实后端」只需把 `USE_MOCK` 改成 `false`，页面一行不用改。

## 四、总体设计

### 4.1 分层

```
页面层  pages/articles | pages/login | pages/store
   ↓ 只调用业务函数、只处理状态
业务层  service/api.js        fetchArticles() / login()
   ↓ 只描述接口契约
传输层  service/request.js    baseURL / 超时 / 拦截器 / 错误归一化
   ↓ 同一个契约（mock 或真实）
数据层  service/mock.js（演示）  |  真实后端
   
横向    service/storage.js（KV + TTL）  service/secure.js（哈希 + 脱敏）
```

关键点：**页面不认识 `uni.request`，也不认识 HTTP 状态码**，它只认 `RequestError.type`。

### 4.2 状态机

```
                 ┌───────── load() ─────────┐
                 ▼                          │
   (初始) ──► loading ──成功且有数据──► success
                 │  └──成功但 list=[]──► empty
                 └──抛错───────────────► error ──重试──► loading
```

`status` 只有四个取值，UI 用 `v-if / v-else-if` 一一对应，避免多布尔量组合出非法状态。

### 4.3 错误分类

| type | 来源 | 处理建议 |
| --- | --- | --- |
| `timeout` | `errMsg` 含 timeout | 提示重试，必要时降低分页大小 |
| `network` | 其它 fail | 检查网络 / 提示稍后重试 |
| `http` | 状态码非 2xx | 记录日志；5xx 提示服务不可用 |
| `business` | `body.code !== 0` | 直接展示后端 `message`（如「账号或密码错误」） |
| `parse` | 返回结构不符合契约 | 视为接口变更，打点告警 |

## 五、实现过程

### 5.1 服务层：request.js

```js
export const BASE_URL = 'https://api.exp05.example.com/v1'
export const TIMEOUT = 8000
export const USE_MOCK = true

function requestInterceptor(config) {
  const token = uni.getStorageSync('exp05:token')
  return {
    method: 'GET', timeout: TIMEOUT, ...config,
    header: {
      'Content-Type': 'application/json',
      'X-Client': 'uni-app-exp05',
      ...(token ? { Authorization: 'Bearer ' + token } : {}),
      ...(config.header || {})
    }
  }
}

function responseInterceptor(res, url) {
  const statusCode = res.statusCode || 0
  const body = res.data
  if (statusCode < 200 || statusCode >= 300) {
    throw new RequestError(ERROR_TEXT.http + '（HTTP ' + statusCode + '）',
      { type: 'http', status: statusCode, code: statusCode, url })
  }
  if (body && typeof body === 'object' && 'code' in body && body.code !== 0) {
    throw new RequestError(body.message || ERROR_TEXT.business,
      { type: 'business', code: body.code, status: statusCode, url })
  }
  return body && typeof body === 'object' && 'data' in body ? body.data : body
}
```

三个拦截点各自只做一件事：拼地址与请求头、判 HTTP/业务码、失败归一化。

### 5.2 业务层：api.js

```js
export async function fetchArticles(params = {}) {
  const data = await get('/articles', { page: params.page || 1, pageSize: params.pageSize || 6 })
  return { list: data.list || [], total: data.total || 0, page: data.page, pageSize: data.pageSize }
}

export async function login({ username, password }) {
  const data = await post('/login', { username, password })
  if (!data || !data.token) throw new RequestError('登录返回数据缺少 token', { type: 'parse' })
  return data
}
```

### 5.3 列表页三态（articles.vue）

```js
const status = ref('loading')   // loading | success | empty | error

async function load(reset = false) {
  if (reset) page.value = 1
  status.value = 'loading'
  try {
    const data = await fetchArticles({ page: page.value, pageSize: pageSize.value })
    total.value = data.total
    if (!data.list.length) { list.value = []; status.value = 'empty'; return }
    list.value = reset ? data.list : list.value.concat(data.list)
    status.value = 'success'
    const savedAt = Date.now()
    storage.set(KEYS.lastLoad, { at: savedAt, count: data.total, page: data.page })
    lastLoadText.value = formatTime(savedAt) + '（共 ' + data.total + ' 篇）'
  } catch (err) {
    status.value = 'error'
    errorText.value = err.message
    errorType.value = err.type
    errorCode.value = err.code
  }
}
```

界面标注：顶部徽标 `请求中 / 成功 / 成功（空数据）/ 失败`，右侧附带 `状态 = error · network` 这样的
调试信息；三种面板分别是骨架屏、空态插画、失败卡片（带错误码与重试按钮）。

### 5.4 KV 存储（storage.js）

```js
const PREFIX = 'exp05:'

set(key, value, ttlMs = 0) {
  const now = Date.now()
  uni.setStorageSync(PREFIX + key, { value, savedAt: now, expireAt: ttlMs > 0 ? now + ttlMs : 0 })
}

get(key, fallback = null) {
  const record = uni.getStorageSync(PREFIX + key)
  if (!record || typeof record !== 'object') return fallback
  if (record.expireAt && Date.now() > record.expireAt) {
    uni.removeStorageSync(PREFIX + key)
    return fallback
  }
  return record.value
}
```

- 命名空间：只清理/枚举 `exp05:` 前缀，不和同域其它应用打架。
- TTL：token 设 7 天，`lastLoadAt` / `session` 长期有效，读取时自动判过期。
- 枚举：`entries()` 直接喂给「本地存储」页面做明细表。

### 5.5 安全：密码不落明文（secure.js）

```js
// 随机盐 + SHA-256（纯 JS 实现，三端可用，已用 Node crypto 交叉验证）
const salt = randomSalt(16)
const digest = digestPassword('123456', salt)  // sha256(salt + '::' + 密码 + '::exp05')

storage.set(KEYS.session, {
  account: user.nickname,
  phoneMasked: maskPhone(user.phone),    // 138****2201
  tokenMasked: maskToken(token),         // mock-t****2768（长度 24）
  salt, digest, loginAt: Date.now()
})                                       // 明文密码：未存储
```

对照反例（本工程没有这样做）：

```js
// ❌ 一旦设备存储被读走，密码就泄露，还会连带其它平台的同密码账号
uni.setStorageSync('user', { account: 'colacolaco', password: '123456' })
```

### 5.6 启动时读取（App.vue）

```js
onLaunch() {
  const session = storage.get(KEYS.session)
  const lastLoad = storage.get(KEYS.lastLoad)
  console.log('[App] 启动时读取本地 KV：', { 登录记录: session ? session.account : '无', 上次加载时间: lastLoad ? lastLoad.at : '无' })

```

## 八、遇到的问题与解决

| 问题 | 现象 | 原因与解决 |
| --- | --- | --- |
| 端口被占 | 5173/5180/5181/5182 已被前几个实验占用 | `vite.config.js` 固定 `port: 5183` + `strictPort: true` |
| 127.0.0.1 打不开 | 浏览器报 `ERR_CONNECTION_REFUSED`，但终端显示 ready | Vite 只监听 `localhost`（IPv6 `::1`），改用 `http://localhost:5183/` |
| 超时态抓不到「请求中」 | 一点「请求超时」立刻变成失败面板 | mock 的 timeout 分支原先只等 900ms；改为 timeout/slow 场景统一 `+4000ms` 再报错，才看得到 loading |
| 失败面板标题写死 | 超时也显示「网络失败」 | 标题改为 `computed`：`errorType === 'timeout' ? '请求超时' : '网络失败'` |
| 模板里直接打印了对象 | 页面出现 `{ "loading": "请求中"…}` | 写成 `{{ requestStateText }}` 打印了整个映射表，改为 `{{ requestStateText[requestState] }}` |
| `npm run build` 被拦 | `npm.ps1 cannot be loaded because running scripts is disabled` | PowerShell 执行策略限制，改用 `node node_modules/@dcloudio/vite-plugin-uni/bin/uni.js build` |
| SHA-256 自测 | 担心三端哈希结果不一致 | 用 Node `crypto` 交叉验证空串/`abc`/中文/emoji/长串，全部一致 |

## 九、心得体会

1. **服务层的价值在「收敛」而不是「多写一层」**：`baseURL`、超时、错误码一旦只出现一次，
   后面每加一个接口都是纯增量的三行代码，页面也从此不需要 `try/catch` 里判断 `statusCode`。
2. **三态要按状态机想，不要按布尔量想**：一开始我用 `loading` + `list.length === 0` + `errorText`
   三个变量拼状态，结果「刷新失败但旧数据还在」时界面自相矛盾；改成单值 `status` 后彻底消失。
3. **持久化要顺手做，而不是事后补**：把「写 KV」放在请求成功的那一行，既证明了持久化，
   又天然得到「上次成功加载时间」这类对用户有用的信息。
4. **安全是习惯不是功能**：把密码塞进 Storage 只要一行，改掉却要改流程（不传明文、服务端哈希）。
   这次的做法（脱敏 + 盐 + 摘要 + 过期）成本很低，但把「明文落盘」这条最危险的路堵死了。
5. **可演示性也是工程质量**：内置 mock 的四种返回（正常/空/失败/超时）让「三态」从口头描述
   变成可以随时复现的界面，答辩和自查都省事。
